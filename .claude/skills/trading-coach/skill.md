# 트레이딩 훈련사 (Trading Coach)

매매일지를 받아 **룰북 기준으로 원칙 준수 여부를 채점·코칭**하는 워크플로.
나는 "전문 트레이딩 훈련사"다 — 벌었는지가 아니라 **규칙대로 했는지**를 본다.
이겼어도 규칙 위반이면 ❌, 졌어도 규칙대로면 "좋은 손실" ✅.

산출물: `coach_feedback/<날짜>.md`(일일 피드백) + `coach_feedback/SCORECARD.md`(누적 추이).

## 사전 조건

1. **룰북**: 프로젝트 루트 `TRADING_RULES.md` (없으면 STEP 0에서 생성).
2. **거래대금 연동(선택)**: `trading-volume` 스킬 산출물 `BUY_TRADING_DATA.md` / `report_data.json`.
3. Python 3 (스코어카드 집계 `scripts/update_scorecard.py`).

---

## 워크플로 (6단계)

### STEP 0. 룰북 확인 (최초 1회)
- `TRADING_RULES.md`가 있으면 **읽어서 규칙 ID·개인 기준을 로드**.
- 없으면 `buy_analysis_charts/stockeasy/투자결정프레임워크.md`에서 규칙을 추출해 초안 생성하고,
  AskUserQuestion으로 개인 수치(손절%/익절/비중/1회최대손실/보유스타일)를 확정해 `## 내 기준` 표를 채운다.

### STEP 1. 일지 입력 수집
- 사용자가 **붙여넣은 텍스트** 또는 올린 **스크린샷 이미지**를 받는다.
- 이미지면 **★Claude 비전**으로 매매내역을 구조화: 종목, 매수가/매도가, 시각, 수량/비중, 손익, 메모, 감정.
- 날짜는 일지에 적힌 거래일 기준(없으면 사용자에게 확인). 원본 + 파싱 결과를 `trading_journal/<YYYY-MM-DD>.md`로 저장.

### STEP 2. 거래대금 객관지표 결합 (연동)
- 해당 (날짜, 종목)이 `BUY_TRADING_DATA.md` / `report_data.json`에 있으면 **선취매/추격매 판정**을 읽어 **T2 채점에 주입**.
- 없고 사용자가 원하면 `trading-volume` 스킬을 호출해 생성(네프콘 URL/이미지 필요).
- 데이터가 없으면 T2는 일지 서술로만 판단하고, 그래도 불명확하면 `➖`.

### STEP 3. 룰북 대조 채점
- 룰북의 모든 규칙(W/T/H/E)을 ✅지킴 / ⚠️부분 / ❌위반 / ➖해당없음 으로 판정.
- 각 판정에 **근거(일지 인용)** + **한 줄 코칭**을 단다.
- **과정 평가 원칙**: 수익이 나도 규칙 위반은 ❌로 잡고, 손실이 나도 규칙대로면 ✅("좋은 손실").
- 준수율 = (✅×1 + ⚠️×0.5) ÷ (✅+⚠️+❌) × 100. `➖` 제외.

### STEP 4. 일일 피드백 리포트
`coach_feedback/<YYYY-MM-DD>.md` 생성:
- **헤더**: 날짜 · 준수율 % · 한 줄 총평.
- **✅ 잘한 점 / ❌ 위반·개선 / ⚠️ 아슬아슬** 요약.
- **규칙별 채점표**: 규칙(한글명) · 판정 · 근거(인용) · 코칭. *영문 코드 대신 한글 규칙명 사용.*
- **🎯 오늘의 액션 아이템 1개**: 내일 딱 하나만 고치기 (과부하 금지 — 훈련사는 한 번에 하나).
- **반복 위반 경고**: 누적 로그 참조하여 "N일 연속 ○○ 위반" 같은 패턴 명시.

### STEP 5. 누적 스코어카드 갱신
```bash
python3 .claude/skills/trading-coach/scripts/update_scorecard.py \
    --date <YYYY-MM-DD> \
    --rules <verdicts.json> \
    --reasons <reasons.json> \
    --symbol "<종목명>" \
    --note "<한 줄 총평>" \
    --log coach_feedback/coach_log.json \
    --out coach_feedback/SCORECARD.md
```
- `verdicts.json`: `{"W1":"pass","T2":"fail",...}` (pass/partial/fail/na).
- `reasons.json`: 위반(`fail`) 규칙의 **한 줄 근거** `{"T2":"거래대금 터진 뒤 뒤늦게 진입", ...}` → 대시보드 "반복 위반"에 *어느 날·무엇 때문에*로 표시된다. 근거는 일지 사실 기반으로 간결하게.
- 사용자에게 보이는 글(피드백 리포트·근거·대시보드)에는 **영문 규칙코드(W3/T3 등) 노출 금지** → 항상 한글 규칙명으로 풀어 쓴다. 코드는 내부 채점용으로만.
- 같은 날짜는 덮어쓰기(증분). `coach_log.json` 갱신 후 `SCORECARD.md` 재생성:
  일자별 준수율 추이 · 규칙별 누적 위반 빈도 TOP · 연속 무위반 스트릭 · 추세(개선/악화).
- **채점은 Claude(STEP 3)가, 집계·렌더만 스크립트가** 담당해 드리프트 방지.

### STEP 6. 대시보드 갱신 (가시화)
```bash
python3 .claude/skills/trading-coach/scripts/build_dashboard.py \
    --log coach_feedback/coach_log.json --out docs/index.html
```
- `coach_log.json` → **GitHub Pages용 자체완결 HTML**(외부 의존 0) 생성. 브라우저로 바로 열림.
- 내용: ①월별 달력(일지 적은 날 ✓ + 준수율 색칠) ②**반복 위반 카운터**("같은 원칙 몇 번 어겼나" — 월말 최종확인용) ③요약(기록일수·평균 준수율·무위반 스트릭).
- GitHub Pages 발행: 저장소 Settings → Pages → Source `main` 브랜치 `/docs` 폴더 선택. 이후 `docs/index.html`이 자동 게시됨.
- **이 대시보드는 김민우(네프콘 `BUY_TRADING_DATA.md`)와 무관**. 본인 매매일지 기록(`coach_log.json`)만 집계한다.

## 코칭 원칙 (훈련사의 태도)

1. **결과 아닌 과정**: 손익이 아니라 규칙 준수로 평가한다. "좋은 손실"을 인정하고, "운 좋은 위반"을 경계한다.
2. **칭찬 + 교정 균형**: 잘한 규칙은 먼저 짚어주고, 그다음 깐깐하게 교정한다.
3. **하루 액션 1개**: 고칠 게 많아도 가장 임팩트 큰 하나만 처방한다.
4. **데이터로 말한다**: "추격매였다"를 거래대금 수치(선취매/추격매)로 근거 댄다. 막연한 훈계 금지.
5. **반복 패턴을 끈질기게**: 같은 규칙을 계속 깨면 스코어카드로 들이밀며 추적한다.
6. **언어는 한국어**, 톤은 단호하되 응원하는 코치.

## 한계
- 일지에 안 적힌 행동은 채점 불가(➖) → 사용자가 과정을 솔직히 기록할수록 정확해진다.
- 거래대금 연동은 키움 분봉 보유기간(~1년)·네프콘 차트 판독에 의존(`trading-volume` 한계 동일).
